## 2026-07-12 - Nested Interactive Element Accessibility
**Learning:** When an icon-only interactive element (such as a `<Button>`) is nested inside a wrapper link (`<a>` tag) that provides a `title` or `aria-label`, the innermost interactive element still needs to be correctly identified by screen readers, and potentially removed from the tab sequence if the outer wrapper is focusable. However, if the inner element is a `<Button>`, this creates invalid HTML (`<button>` inside `<a>`).
**Action:** When identifying `<Button>` nested inside `<a>`, it's better to refactor the element to remove the invalid HTML nesting. Use the wrapper `<a>` as the interactive element and style it appropriately, or change the `<Button>` to be an `<a>` with `href`. Or apply the necessary `aria-label` and `tabIndex={-1}` to the inner element if refactoring is not feasible.
