## 2026-05-15 - Command Injection and Credential Leakage in Gateway shell.exec
**Vulnerability:** The `shell.exec` method in `tui_gateway/methods_tools.py` executed shell commands using `subprocess.run(shell=True)` without an explicit, sanitized environment. The `tui_gateway` daemon typically holds highly sensitive API keys and provider credentials in its active `os.environ`. By omitting `env=...`, the subprocess implicitly inherited the parent's full environment, creating a severe credential leakage vector if malicious or untrusted inputs dictated the shell command (or if the command's underlying tool dumped its environment).
**Learning:** In long-running background daemons (like `hermes gateway`), the host process's memory space and environment variables accumulate and persist secrets. Explicitly isolating subprocesses from the parent's ambient environment is crucial, even for internal tools, to prevent environment leakage.
**Prevention:** Always explicitly define a tightly scoped or sanitized `env` parameter (e.g., using `build_subprocess_env()`) for all `subprocess.run` calls, especially those using `shell=True` or interacting with unconstrained inputs in high-privilege daemons.
