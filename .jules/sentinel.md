## 2026-07-19 - Enforce HTTP/HTTPS Scheme Validation for urllib.request.urlopen
**Vulnerability:** The standard library `urllib.request.urlopen` function allows non-HTTP schemes like `file://` if not explicitly restricted. When user-controlled input flows into `urlopen` without schema validation, this results in a Server-Side Request Forgery (SSRF) and Arbitrary Local File Read vulnerability. This was observed across multiple files (`tools/osv_check.py`, `tools/tirith_security.py`, `tui_gateway/server.py`, `agent/anthropic_adapter.py`, `tools/discord_tool.py`, `gateway/relay/__init__.py`).
**Learning:** `urllib.request.urlopen` is overly permissive by default. Relying on network timeouts and assuming standard HTTP traffic based on variable names like "url" or "endpoint" is insufficient defense against `file://` SSRF attacks.
**Prevention:** Always validate that URLs provided to `urllib.request.urlopen` start with `http://` or `https://` before constructing a `Request` or calling `urlopen`. Use `# nosec B310` to suppress Bandit warnings only after explicit scheme validation is present.
