## 2026-07-24 - Pre-compile Regexes and Fast-path Early Returns in Tag Stripping
**Learning:** In string processing loops dealing with extensive markdown or reasoning block stripping (like `strip_think_blocks`), executing multiple `re.sub` passes dynamically is slow. Consolidating patterns into pre-compiled regex objects at the module level significantly reduces runtime parsing overhead. Additionally, applying a fast-path early return (`if '<' not in content: return content`) avoids all regex execution entirely when no tags are present, leading to drastic performance improvements for standard text.
**Action:** When implementing or optimizing text processing functions, always pre-compile regular expressions globally. If the target modifications require a specific structural indicator (like `<` for tags), apply a fast-path check to exit immediately if the indicator is missing.
